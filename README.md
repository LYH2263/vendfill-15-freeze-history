# VendFill 售货机补货

按货道容量、库存与在途量计算缺口，生成不超缺口、非负的补货单。

补货单按**世代**严格隔离：

- **历史单（冻结）**：任意一次成功生成后，该单的逐行补量、状态连同当时的库存/在途/容量整体冻结。之后再改货道库存、在途或容量，打开历史单仍显示生成当时的数字，绝不被现算覆盖，也不会在改库存时被批量改写。
- **当前缺口（现算）**：「当前缺口」视图与「满仓」「汇总」始终按货道最新数据现算，不落库；只有再次点「生成」才会冻结出反映新缺口的新一代。
- **行漂移检测**：历史单逐行带签名。若库内行文本被截短或改脏，详情与列表仍按库内脏文本原样读出，并单独标出「行已漂移」，不会静默写回修复。

技术栈：Python 3.12 / FastAPI / SQLAlchemy / PostgreSQL / Vue 3 / TypeScript / Vite

## 启动

```bash
docker compose up --build
```

| 服务 | 地址 |
| --- | --- |
| 前端 | http://localhost:4800 |
| API | http://localhost:9800 |
| API 文档 | http://localhost:9800/docs |
| Postgres | localhost:5449 |

健康检查：`GET http://localhost:9800/api/health`

## 使用说明

1. 在「货道格子」直接修改库存 / 在途 / 容量并保存：只影响「当前缺口」与之后生成的新单，历史单不变。
2. 在「销量」了解近期出货。
3. 打开「补货小票」：「当前缺口·现算」页实时看缺口并可改数；点「生成补货单」冻结为新一代，在「历史补货单·冻结」页按世代并排查看。
4. 在「满仓」「汇总」查看按当前货道现算的已满货道与补货合计。

## 接口世代约定

| 接口 | 世代 |
| --- | --- |
| `POST /api/refills/run` | 显式生成新一代并冻结（唯一写历史单入口） |
| `GET /api/refills`、`/api/refills/{id}`、`/api/refills/latest` | 历史冻结单，纯读；脏文本原样返回并带漂移标注 |
| `GET /api/refills/current`、`/view/full`、`/view/summary` | 货道现算，不落库 |
| `PATCH /api/lanes/{id}` | 改库存/在途/容量，仅影响现算与后续新单 |

```bash
docker compose exec api pytest -q
```
